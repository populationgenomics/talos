Communicate tersely. `GLOSSARY.md` fixes the domain vocabulary (cohort, annotation products, reanalysis cycle,
history, dataset, access level...) — use its terms, and avoid the ones it lists under _Avoid_.

## Commands

Python env is managed by `uv` (`uv.lock` is authoritative for the container build).

```bash
uv sync --frozen --extra test          # dev install
uv run pytest -n auto                  # full suite, parallel via pytest-xdist (in the test extra)
uv run pytest test/test_moi_tests.py -k test_genotype_calls   # single test
uvx ruff check . && uvx ruff format --check .                 # lint (config in pyproject.toml)
uv run pre-commit run --all-files      # ruff + mypy + cpg-id-checker, as run by hooks
uvx bump-my-version bump patch         # version bump — touches 6 files, see [tool.bumpversion]
uv run --extra docs mkdocs serve       # docs preview (CI runs `mkdocs build --strict`)
nextflow lint main.nf                  # CI lints Nextflow too (strict v2 parser syntax)
```

One container for every process, built locally, not pulled (`params.container` in `nextflow.config`).
It carries the Python package, bcftools/htslib, echtvar and SVAFotate; only GATK SVAnnotate runs
elsewhere, from a public image (`params.gatk_container`). The tag must match `params.container`:

```bash
docker build -t talos:13.0.0 .
```

Nextflow entrypoints (all take `-c nextflow.config`):

```bash
nextflow -c nextflow.config run preparation.nf   # refresh ClinVar/PanelApp/AlphaMissense/mito resources
nextflow -c nextflow.config run main.nf     --input_tsv nextflow/inputs/test.tsv --outdir <dir>
nextflow -c nextflow.config run cpg_main.nf --cohort_ids COH1,COH2 --access_level test --sequencing_type genome --talos_config <toml>
```

`main.nf` and `cpg_main.nf` need the raw sources in `params.large_files` (`large_files/gather_files.sh` downloads them) and a
`preparation.nf` run for the current month.

`nextflow/inputs/test.tsv` (no SV) and `test_sv.tsv` (SV path) are the toy fixtures; the VCFs are
generated by `nextflow/inputs/generate_*_test_data.py`. `--outdir` is required by `main.nf`.

End-to-end regression cases live in `nextflow/inputs/cases/<case>/` (a VCF plus `expected.json`), listed in
`nextflow/inputs/multicase_test.tsv`, one cohort per case. Run them through `main.nf`, then compare against
the next-cycle TSV the run writes to the root of `--outdir`:

```bash
uv run python nextflow/inputs/check_test_cases.py <outdir>/talos_input_YYYYMMDD.tsv
```

## Architecture

Talos is a Nextflow pipeline over a Python package (`src/talos`). Nextflow modules are either bash commands,
or thin invocations of talos modules using `python -m talos.MODULE`. Most modules run `export TALOS_CONFIG=...`.

### Three workflows

1. **`preparation.nf`** — cohort-independent. Downloads/reformats ClinVar (via ClinvArbitration),
   PanelApp, MANE, AlphaMissense, mito sources into `params.processed_annotations`. Outputs are
   month-stamped (`clinvarbitration_YYYY-MM.*`, `panelapp_YYYY-MM.json`); `talos.nf` hard-exits if
   the current month's files are absent. Run this on a cadence, not per-cohort.
2. **`nextflow/annotation.nf`** (+ `sv_annotation.nf`) — expensive, idempotent, effectively run
   once per callset. Merge → scatter regions → `bcftools norm` → `echtvar anno` (gnomAD,
   AlphaMissense) → `bcftools csq`, then a per-cohort shard manifest. Cohorts whose manifest (or
   annotated SV VCF) already exists under `${cohort}_annotated/` are reused, not re-annotated —
   delete that directory to force re-annotation. SV path is separate: GATK SVAnnotate → SVAFotate
   → field rename.
3. **`nextflow/talos.nf`** — cheap, run every cycle. This is where reanalysis happens. ClinVar is
   deliberately *not* baked in at annotation time: `AnnotateVcfWithFreshClinvar` applies the
   current month's ClinvArbitration echtvar zip to every shard each cycle. `StartupChecks` runs on
   the first shard per cohort before anything else.

2+3 live in the shared `TALOS_PIPELINE` (`nextflow/talos_pipeline.nf`), which takes one Map per cohort
(every input TSV column plus `annotated_dir`/`analysis_dir`). Two thin entrypoints build those rows:
`main.nf` from `--input_tsv` (reanalysis cycles just re-run it; it also writes a next-cycle TSV with `history`
repointed at this run's results), and `cpg_main.nf` from Metamist cohorts via `InputTsvFromMetamist`, publishing
to dataset buckets and optionally registering results back (`docs/CpgDeployment.md`, `src/talos/cpg_internal/`).
A change to cohort-row columns or output layout must be made in both. Under `main.nf`, annotation
products publish to `${outdir}/${cohort}_annotated/`, analysis results to `${outdir}/${cohort}_analysis_YYYYMMDD/`.
Publishing is process `publishDir`, never workflow outputs (`docs/adr/0001`): the entrypoint computes each
cohort's `annotated_dir`/`analysis_dir` and carries them in the cohort rows (`meta.analysis_dir`); `TALOS_PIPELINE`, subworkflows and modules never build output paths themselves.

### Channel shape in talos.nf

Two spines, deliberately distinct — get this wrong and processes silently stall:

- `ch_meta` — **one row per cohort**: `[cohort, meta]`, `meta` being the cohort row Map from `TALOS_PIPELINE` (file
  columns already resolved to Paths or `[]`, plus `analysis_dir`, `report_dir`, `has_sv`). Read fields by name
  (`meta.pedigree`); `ch_ctx = UnifiedPanelAppParser.out.join(ch_meta)` → `[cohort, panelapp, meta]` feeds most stages
- `ch_shards` — **one row per annotated shard**: `[cohort, vcf]`

Fanning per-cohort metadata across shards uses `combine(..., by: 0)`, never `join` (a join matches
one shard and strands the rest). Absent optional inputs are represented by an empty list `[]` (an
empty/absent TSV cell parses to `''`/`null`, both falsy), which stages nothing; channel logic and
module scripts branch on plain truthiness. `join(..., remainder: true)` is avoided on purpose — see the comment above
`ch_sv_resolved`; it emitted a bare String key when the right-hand channel never emitted, silently
emptying every downstream join. Instead, cohorts without SV/mito data get `[cohort, []]` mixed in directly
(`meta.has_sv` / `meta.mito`).

### The three variant streams

Small variants, SVs, and mitochondrial variants are filtered and labelled independently, then
converge on **`ValidateMOI`**, which is the only stage that sees all of them:

| Stream  | Script                           | Scatter                                     |
|---------|----------------------------------|---------------------------------------------|
| Small   | `run_small_filtering.py`         | per shard, gathered by `ConcatLabelledVcfs` |
| SV      | `run_sv_filtering.py`            | per cohort                                  |
| Mito    | `reformat_and_label_mito_vcf.py` | per cohort                                  |

STRs are a fourth, unlabelled input: the `str` TSV column (a `scripts/stripy_json_to_vcf.py` VCF) goes straight from
`ch_meta` to `ValidateMOI --str`, and `create_str_variant` in `utils.py` assigns the `str` category on read.

`validate_moi.py` reads the labelled VCFs, builds pydantic models, and runs `moi_tests.py`;
`hpo_flagging.py` then annotates phenotype matches, and `create_talos_html.py` renders the report.
Gene/panel context for all of it comes from `unified_panelapp_parser.py`.

### Category labels

Categories are the core extension point. A category is written into the labelled VCF as an INFO
field whose **name encodes its semantics** (see `docs/AddingNewCategories.md`):

- `categoryboolean<NAME>` — `0`/`1`, applies to every sample with the call
- `categorysample<NAME>` — comma-delimited sample IDs, or `missing` (e.g. de novo)
- `categorydetails<NAME>` — bespoke payload parsed on ingestion into boolean/sample + `info` dict (e.g. PM5)

Downstream code branches on these prefixes. Adding a category means: config entry, a self-contained
labelling function in `run_small_filtering.py` (or the mito/SV equivalent), a call site, inclusion in the filter,
and (details only) parsing in `utils.py` ingestion.

### Result versioning

`models.py` carries `CURRENT_VERSION` and an `ALL_VERSIONS` chain, with one module per hop in
`src/talos/liftover/`. Old `ResultData`/`PanelApp` JSON is lifted forward on read
(`lift_up_model_version`) so reanalysis can consume historical results. **Any breaking change to existing models needs a
new version, a new liftover module, and a test in `test/model_liftovers/` (JSON fixtures live in
`test/input/models/`).**

### Configuration

Two independent config layers, easy to confuse:

- **Talos app config** — a TOML file, located via the `TALOS_CONFIG` env var, read through
  `talos/config.py::config_retrieve(['Section', 'key'], default)`. Baseline:
  `src/talos/example_config.toml`; reference: `docs/Configuration.md`. Passed per-cohort as the
  `config` column of the input TSV.
- **Nextflow config** — `nextflow.config` (`params` + per-process resources), `docs/NextflowConfiguration.md`.

**Section names don't map 1:1 to modules.** `unified_panelapp_parser.py` reads `['GeneratePanelData', ...]`
(plus `PanelApp`), `run_sv_filtering.py` reads both `RunSvFiltering` and `RunSmallFiltering`, and
`run_small_filtering.py`/`moi_tests.py` both read `RunSmallFiltering` and `ValidateMOI`. Check the actual `config_retrieve`
call before adding a key; don't assume the section matches the module.

## Conventions

Ruff, line length 120, **single quotes**, broad rule set (see `[tool.ruff.lint]`). Logging is `loguru`. Data models are pydantic v2.
Python is pinned to `>=3.10,<3.13`. Update `CHANGELOG.md` under the
`<!--latest-start-->`/`<!--latest-end-->` markers — `docs/index.md` includes that span verbatim.
